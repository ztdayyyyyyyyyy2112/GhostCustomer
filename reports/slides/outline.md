# Presentation slide outline

Target: a concise talk that all four members can explain. Use real result figures only after they are generated. The order below supports the required statistics-to-ML narrative.

| Slide | Main point | Evidence needed |
| --- | --- | --- |
| 1 | Title, team, research question | Final project title and team details |
| 2 | Why silent disengagement matters | Business context and operational definition |
| 3 | Dataset and provenance | Source/license, period, event types, actual counts |
| 4 | Time design and cohort | Baseline/observation/T/confirmation diagram and exclusions |
| 5 | Descriptive behavior | Histogram/boxplot with group N and units |
| 6 | Inferential results | Hypotheses, test assumptions, CI, p, effect size |
| 7 | Regression | Coefficients/OR with CIs, diagnostics, interpretation |
| 8 | Forecast | Actual/fitted/future, baseline, intervals, error metrics |
| 9 | ML evaluation | Majority and Decision Tree benchmarks versus logistic/RF on the same held-out split; PR-AUC, recall/precision, calibration |
| 10 | Explainability and limits | Verified feature attribution; no causal wording |
| 11 | Dashboard demo | Overview → customer timeline → stats → forecast → predict |
| 12 | Conclusions and limitations | Answers to RQ1–RQ4 and study constraints |

Place SEM status where it fits the final lecturer decision. Clearly identify mock screens if the live backend is unavailable at recording time. Never put invented numerical results on slides.
